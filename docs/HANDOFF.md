  캔버스는 쓰지 않는다. 일시 정지하면 손이 그 자리에 멈추고, 재개하면 이어서 누른다. 테스트 `e2e/cpu-hand.spec.ts`,

- **머니 컷인(2026-10-05, `main`).** 모든 구매·건설·통행료·인수·월급·세금·카드 돈·매각·파산이 전체 화면 컷인으로
  재생된다: 주인공(땅·건물·도시 카드·금고·은행·세무서)이 짧은 변의 약 60–67 %, 각 플레이어의 금·은·동 코인 더미가 자기
  좌석 가장자리(짧은 변의 약 16–25 %)에 서고, 코인이 실제 좌석 사이를 날아간다(빠질 때 하강음, 쌓일 때 상승 래더 +
  챠링). 모두에게 걷기는 중앙 금고에 모였다가 합계 명판 뒤 받는 사람에게 간다. 보드·패널은 컷인이 손을 놓을 때 바뀐다.
  기획·결과: `docs/MONEY-EVENTS.md` §11. 연결: `src/ui/fx/moneymap.ts`(이벤트 → 장면, 순수) + `animate.ts`(재생) +
  `GameView.money`(무대). 보는 법: 아무 게임에서 땅을 사거나 남의 땅에 서면 된다. 개발용 단독 데모는
  `npm run dev` 후 `/money-demo.html`. 테스트 `e2e/money-events.spec.ts`, 스크린샷 `e2e/__screenshots__/money-*.png`,
  필름스트립 `docs/assets/money-ingame/*.jpg`. 보드 카메라(뒤로 물러나기/3D 기울임)는 high 등급(그리고 작은 화면의 mid)에서만
  켜진다: 보드가 27 MB 레이어가 된다(§13.3). 성능 게이트 `Paint ≤ 20/s`는 컷인 때문에 넘는다(약 24/s, §11.4).
  **비트 확장(제품 책임자 피드백 "너무 빨리 지나간다")**: 모든 컷인이 화면에 3초 이상(보통 3.7–5.3초), 등장·예비 동작 →
  코인 → 결과 → 명판 → 1초 이상 정지 → 0.3초 퇴장(§12). CPU 턴 17.2 → 약 20–21.6초(이 컨테이너), 사람 굴림 → 결정 6.1초
  그대로. 실제 태블릿에서는 아직 못 봤다. **기기별 연출 해상도·3D 연출**(§13): 자동 등급(high 1.0 + 3D, mid
  0.75, low 0.5 2D)을 deviceMemory와 기기 픽셀로 고르고, 설정 → 연출 해상도(자동/높음/낮음)·3D 연출(자동/켬/끔)로
  바꿀 수 있다. 등급마다 레이어 메모리 예산(250/150/100 MB), 컷인 프레임이 두 번 연속 나쁘면 한 등급 내리는 안전장치.
  실제 래스터 배율 확인: `node scripts/fx/money-raster.mjs`.
- **고정 화면(2026-10-05, `feat/fixed-view`).** 사람이 정확히 한 명이고 나머지가 CPU면 혼자 하는 게임이므로
  화면을 그 사람에게 고정하고 아무것도 돌리지 않는다(사용자 요청: "사람 1명 + 나머지 CPU면 화면 회전 없이 그 사람
  기준으로 고정"). 사람은 셋업에서 어느 자리에 앉든 화면 아래(S)에 그려지고, 다른 사람들은 상대 위치를 유지한다
  (탁자를 90° 단위로 돌림. 엔진 자리·차례·저장은 그대로). 스테이지는 매 턴 0°, 패널 4개 모두 똑바로, 보드 윗줄
  글자도 S 기준으로 똑바로, 돈 연출은 S를 향해 패 하나(전원에게 걷기도 합계 하나), 지갑은 각자 패널 위에 똑바로,
  결과 화면은 S를 향하고 ↻ 버튼 없음. 머니 컷인의 3D 기울임·보드 카메라(등급에 따라)도 S를 향한다. CPU 손은 여전히 그 CPU의 (그려진) 자리 쪽에서 들어온다. 판단은
  `src/ui/orientation.ts` 한 곳(`orientationFor`), 사람 2명 이상·전원 CPU는 예전 탁자 모델 그대로.
  테스트 `src/ui/__tests__/orientation.test.ts`, `e2e/fixed-view.spec.ts`, 스크린샷
  `e2e/__screenshots__/fixed-*.png`. 실제 태블릿에서는 아직 못 봤다. 설계: `docs/DESIGN.md` §2.1 "Fixed view".
- 사용자에게는 한국어로 답한다. 커밋 제목은 `engine:` `ui:` `fix:` `build:` `docs:` 접두어(AGENTS.md).

## 사용자 환경에서 확인된 사실

- **PC는 원격 데스크톱 세션, 태블릿은 "동작 줄이기" 신호를 보낸다.** 예전 앱은 그 신호를 받으면 모든 연출과
  대기 시간을 0으로 만들어서, 사용자가 요청한 속도·비트·주사위 굴림이 전부 무효였다. 지금은 앱이 기기 신호를
  읽지 않는다. 시간 정책은 `src/ui/fx/time.ts` 머리말 표 한 곳에만 있다. `matchMedia('(prefers-reduced-motion…)')`
  나 CSS 미디어 쿼리를 다시 넣지 말 것.
- **태블릿(삼성, 4:3)은 효과 캔버스를 흰 사각형으로 그린다.** 원인은 기기에서 확인하지 못했다. Android 앱에서는
  캔버스 효과가 기본으로 꺼져 있다(`fxQualityOn`, `src/ui/shell/prefs.ts`). 기본으로 다시 켜지 말 것.
  자세한 기록: `docs/PERFORMANCE.md` "흰 사각형 재발".
- **사용자가 두 번 물은 것: "테스트하고 빌드 만든 거 맞아?"** 테스트 결과를 읽지 않고 빌드를 넘긴 적이 있다.
  결과를 직접 확인하기 전에는 "된다"고 말하지 않는다. 기기에서 확인하지 못한 것은 그렇다고 적는다.

## 검증과 빌드

| 어디서 | 명령 | 비고 |
|---|---|---|
| 클라우드 / Android SDK 없는 곳 | `npm run release:check -- --web` | 타입체크 → 단위 → 전체 e2e(약 17분) → 웹 빌드 |
| 로컬 PC | `npm run release:check` | 위 + `cap sync` → APK → APK 안의 번들 일치 확인 |

- e2e는 추적 중인 스크린샷(`e2e/__screenshots__`, `docs/assets/vfx-ingame`)을 덮어쓴다. 의도한 변경이 아니면
  커밋 전에 되돌린다: `git status --short | grep -E "^ M.*\.png$" | awk '{print $2}' | xargs -r git checkout --`
- 움직임·타이밍·속도를 건드리면 `e2e/pacing.spec.ts`를 본다. 상태가 아니라 화면에 보이는 것(주사위 흔들림,
  굴림 약 1초 뒤 결과, 말이 칸마다 지나가는지, 턴 길이)을 네 환경에서 잰다.
- **APK는 푸시하면 GitHub Actions가 만든다**(`.github/workflows/android.yml`). 저장소 → Actions → "Android" 실행 →
  Artifacts에서 `MoneyPoly-<버전>-<날짜>-<시각>-debug`를 받는다(zip 안에 APK). 사용자는 빌드를 구분할 수 있게
  이름에 버전과 날짜가 들어가기를 원한다.
- 음성·효과음·음악·딜러 스프라이트 생성 스크립트(`scripts/dealer`, `scripts/sound`)는 API 키가 필요하다
  (ElevenLabs, Gemini). 키는 사용자 PC의 환경변수에만 있다. 키가 없는 곳에서는 생성 작업을 하지 않는다.

## 남은 작업

사용자 답을 기다리는 것:

1. 태블릿에서 새 APK 확인 세 가지: 흰 박스가 사라졌는지 / 주사위를 굴릴 때 주사위 자리에 작은 흰 박스가
   보이는지 / 설정 → 연출 품질을 "낮음"으로 켜면 흰 박스가 다시 나오는지. 답에 따라 원인이 캔버스 방식 자체인지
   워커 경로인지 갈린다.
2. 속도 체감. 기본 속도 실측: 사람 턴(굴림 → 결정) 약 6.1초, CPU 턴(6칸 이동 + 구매 + 건설 + 라운드 전환)
   22.6초(아주 느긋하게 27.7초, 아주 빠르게 16.3초). CPU 손을 넣은 뒤: 결정 하나에 약 0.5초(굴리기는 주사위
   흔들림까지 약 0.7초)가 늘었다. 같은 측정(`e2e/pacing.spec.ts`, 클라우드 컨테이너)에서 CPU 턴 15.8초 → 17.4초
   (+1.6초, 3회/7회 평균). 22.6초를 잰 PC에서는 약 24초로 예상한다(직접 재지 않음). 머니 컷인을 연결한 뒤: 같은 측정에서 CPU 턴 17.1–17.9초 → 17.8–18.5초(데스크톱 평균 17.2 → 18.4초, +7 %), 사람 턴(굴림 → 결정) 6.1초 그대로. 컷인 비트를 3초 이상으로 늘린 뒤: CPU 턴 19.9–21.6초.

사용자가 요청했고 아직 안 한 것(위에서부터):

1. **이벤트별 연출 완성도.** (돈 이벤트는 머니 컷인으로 바뀌었다: `docs/MONEY-EVENTS.md` §11. 남은 것은 §11.7.) 사용자 말: "각각의 이벤트를 얼마나 완성도 있게 만들고 시각적으로 즐거우면서
   명확하게 만들고, 사람들이 눈으로 인식하는 과정에 비트가 명확하고 일관적으로 반영돼야 한다." 지금까지는 비트의
   일관성만 맞췄다(`BEAT` in `src/ui/fx/motion.ts`, 순서는 `src/ui/fx/animate.ts`). 구매·건설·통행료·인수·카드·
   축제·무인도·파산·경매를 하나씩 보고 다듬는 작업이 남았다. 픽사 애니메이션 12원칙(예비 동작, 타이밍 등)이 기준이다.
2. **완성도 점수 90점 이상.** 모든 측면에서 다시 채점하고 부족한 곳을 올린다.
3. 게임플레이 2차: 구매 시 다단계 건설, 어려운 CPU와 CPU 성격, 월드 이벤트와 캐릭터 패시브(셋업 토글),
   땅 거래, 튜토리얼.

사용자만 할 수 있는 것: 아이콘·딜러 그림의 권리 확인, ElevenLabs 상업 이용 증빙(`docs/RELEASE.md` 체크리스트).
