# 머니 이벤트 기획서 (Money Events)

> 상태: v1 기획 (2026-10-05). 제품 책임자 요청을 그대로 옮긴 요구사항과, 그 요구를 구현 가능한
> 설계로 바꾼 결정을 함께 적는다. 레퍼런스 리서치: `docs/research/06-money-event-research.md`.
> 구현 순서는 §9. 이 문서가 기존 `docs/VFX.md`의 돈 관련 프리셋(tollPay, coinIn, billRain 등)보다
> 우선한다.

## 0. 요구사항 (제품 책임자, 2026-10-05)

1. 모든 **구매, 돈을 쓰는 일, 돈을 받는 일**은 화면 전체에 보이는 이벤트로 크게 보여 준다.
2. 건물을 사면 **산 건물 이미지를 크고 화려하게** 큰 화면에 보여 주고, **황금 코인이 어디서 나와
   어디로 날아가는지**, 그래서 **어떤 건물이 세워지는지**가 명확해야 한다.
3. 내 돈이 나가면 **현재 내 돈이 얼마인지**를 **금·은·동 코인이 쌓인 정도**로 보여 주고, 거기서
   **코인이 빠져나가는 과정을 실시간으로** 보여 준다.
4. 다른 플레이어에게서 돈을 걷으면 **화면 중앙으로 전부 모였다가 얼마가 모였는지 보여 주고**,
   다시 **받는 사람에게 날아간다**.
5. 돈이 나갈 때는 **돈 빠지는 소리**, 쌓일 때는 **돈 쌓이는 소리**가 난다.
6. 화면을 **입체적으로** 쓴다. 해상도가 부족해 픽셀이 보여도 괜찮으니 **충분히 줌인해서 화면을 꽉
   채운다**. 그래야 모바일 게임처럼 풍성해 보인다.
7. **비트가 중요하다.** (기존 원칙: 예비 동작 → 동작 → 결과 → 정리, `BEAT` in `src/ui/fx/motion.ts`)

## 1. 바꿀 수 없는 제약

| OS 동작 줄이기 신호 무시 | 앱 설정(애니메이션)만 따른다 (`docs/HANDOFF.md`) |

## 2. 무대: 머니 컷인 레이어

- 보드 위, 메뉴 아래에 **전체 화면 레이어 하나**(`.money-stage`)를 둔다. 부팅 때 한 번 만들고, 쓰지
  않을 때는 `transform`으로 화면 밖에 둔다(표시/숨김 Paint 없음).
- **카메라**: 이벤트가 시작되면 보드가 살짝 뒤로 눕고(`rotateX` 8–10°) 0.92배로 물러나며, 비네트
  (정적 방사 그라데이션, opacity만 변화)가 깔린다. 끝나면 되돌아온다. 무대 자체는 `perspective:
  1200px` 컨테이너라 코인이 앞뒤 깊이(`translateZ`, 크기, 그림자)를 갖는다.
- **줌인 원칙**: 주인공 오브젝트(건물, 도시 랜드마크, 중앙 금고)는 화면 짧은 변의 **55–65%**까지
  키운다. SVG는 그대로 커져도 선명하고, 비트맵(코인 스프라이트)은 픽셀이 보여도 허용한다.
- **좌석 배치**: 관련된 플레이어의 지갑 더미는 **그 플레이어의 좌석 가장자리**(S/E/N/W)에 나타나고
  그 좌석을 향해 회전한다. 코인은 실제 좌석 방향 사이를 날아가므로 네 명 모두 공간적으로 읽힌다.
- **중앙 명판**: 금액과 짧은 제목("통행료", "별장 완공!")은 중앙 명판 한 곳에, **행동 좌석 쪽으로**
  회전해서 보여 준다. 금액 숫자는 크고 굵게(Jua), 카운트업/다운한다.

## 3. 지갑 더미 (금·은·동 코인)

- 단위: 게임 화폐는 `만`. **금 코인 = 1,000만, 은 코인 = 100만, 동 코인 = 10만.** 더미 구성은
  현금의 자릿수 그대로다. 예: 3,450만 → 금 3, 은 4, 동 5. 한눈에 "부자 / 가난"이 읽히고, 정확한
  금액도 셀 수 있다.
- 모양: 금·은·동 각각 **세로 기둥**(옆에서 본 코인 단면을 겹쳐 쌓은 스택). 금 기둥은 최대 15개까지
  보이고 넘으면 기둥 위에 `+`. 기둥 아래에 현재 금액 숫자.
- **나갈 때**: 내야 할 금액만큼 코인이 위에서부터 하나씩 튀어 올라 빠져나간다(실시간, 코인 하나마다
  빠지는 소리). 잔돈이 필요하면 **환전 비트**: 금 코인 하나가 반짝이며 은 코인 10개로 쪼개진 뒤
  빠져나간다. 숫자는 코인이 나갈 때마다 내려간다.
- **들어올 때**: 날아온 코인이 기둥 위에 착지하며 쌓이고(작은 바운스), 숫자가 올라간다. 은 10개가
  모이면 금 1개로 합쳐지는 **합치기 비트**(마지막 정리 단계에서 한 번).
- 날아가는 코인 개수는 금액을 그대로 쓰지 않는다. **비행 코인 1개 = 금액 묶음**이며, 금액 등급별로
  8 / 14 / 22 / 32개(최대)로 정한다. 지갑 더미의 실제 증감은 위 단위 규칙을 따른다.

## 4. 이벤트 목록과 비트

모든 시간은 30 fps 기준 프레임(f)과 보통 속도 ms. 등급은 금액과 사건 크기로 정한다.

| 등급 | 조건 | 길이 |
|---|---|---|
| S (작게) | 200만 미만, 은행과의 작은 거래 | 약 1.4 s |
| M (보통) | 200–999만, 건설 L1–L2, 일반 통행료 | 약 2.0 s |
| L (크게) | 1,000만 이상, L3 호텔, 인수, 모두에게 걷기 | 약 2.6 s |
| XL (최대) | 명소(L4), 축제 통행료 2배, 파산 청산 | 약 3.0 s |

### 4.1 공통 비트 (한 번의 돈 이동)

1. **등장 (f0–6)**: 카메라가 물러나고 비네트. 지불자 지갑 더미가 좌석 가장자리에서 솟아오른다.
2. **예비 동작 (f6–10)**: 나갈 코인들이 더미 위에서 살짝 떠오르며 반짝(빠지기 직전의 긴장).
3. **유출 (f10–)**: 코인이 40–60 ms 간격으로 하나씩 빠져나가 호를 그리며 목적지로. 코인마다
   빠지는 소리(짧은 금속음, 음높이 ±1.5 반음 흔들림). 지불자 숫자가 실시간으로 내려간다.
4. **도착**: 목적지에 코인이 쌓이며 쌓이는 소리(코인마다 음높이 사다리 상승). 마지막 코인에
   "착-칭" 소리와 작은 펀치(목적지 1.08배).
5. **결과 (+8 f)**: 결과 오브젝트가 핵심 순간을 보여 준다(건물이 세워짐, 금액 명판 확정 등).
6. **정리 (+10 f)**: 컷인이 빠지고, 결과가 보드의 실제 위치로 날아가 합쳐진다(건물 아이콘이 칸으로,
   지갑 더미가 패널로). 보드 상태는 이때 바뀐다.

### 4.2 이벤트별

| 이벤트 | 출발 → 중간 → 도착 | 주인공 / 결과 비트 |
|---|---|---|
| **땅 구매** | 내 지갑 → 중앙 "빈 땅"(도시 랜드마크 크게, 땅 표지판) | 코인이 땅에 떨어지면 내 색 깃발이 꽂히고 "마닐라 구매!" |
| **건설 L1–L3** | 내 지갑 → 중앙 공사 현장 | 코인이 쏟아지면 먼지 구름 → 건물(별장·빌딩·호텔)이 아래에서 솟아오름(오버슈트) |
| **명소 L4** | 내 지갑 → 중앙 | XL: 망치 3회 → 명소가 화면 60%까지 솟음 → 광선과 반짝임 → "명소 완공!" |
| **통행료** | 지불자 지갑 → **중앙 도시 칸(주인 색 테두리)** → 주인 지갑 | 중앙에서 코인이 모여 금액 명판 확정 → 주인에게 날아감. 축제면 ×2 도장이 찍히며 코인이 두 배 |
| **인수** | 구매자 지갑 → 중앙 도시 → 원래 주인 지갑 | 도시의 테두리 색이 구매자 색으로 도장처럼 바뀜 |
| **모두에게 걷기** (생일 카드 등) | 다른 모든 지갑 → **중앙 금고** → 받는 사람 지갑 | 각 좌석에서 동시에 코인이 모여든다 → 금고가 들썩 → 합계 명판("총 300만!") 한 박자 멈춤 → 금고가 열리며 받는 사람에게 |
| **모두에게 주기** | 내 지갑 → 중앙 금고 → 다른 모든 지갑에 나눠서 | 금고에서 몫만큼 나뉘어 각 좌석으로 |
| **월급 / 보너스 / 기부금 수령** | 은행(화면 위쪽 금고) 또는 기부함 → 내 지갑 | 코인 비가 내려 더미에 쌓임, 숫자 카운트업 |
| **세금 / 기부 / 보석금 / 벌금** | 내 지갑 → 중앙 세무서·기부함·은행 아이콘 | 해당 아이콘이 코인을 삼키고 금액 명판 |
| **매각 (빚 갚기)** | 내 건물(중앙, 크게) → 은행 → 내 지갑 | 건물이 해체되며 코인으로 바뀌어 지갑에 |
| **파산 청산** | 파산자 지갑과 건물 → 중앙 → 채권자 지갑 | XL: 더미가 무너지고 건물이 하나씩 채권자 색으로 |
| **경매 낙찰** | 낙찰자 지갑 → 중앙 도시 | 땅 구매와 같고 망치(낙찰) 소리 |

### 4.3 연속 이벤트

- 같은 행동에서 이어지는 돈 이벤트는 **하나의 컷인으로 합친다**. 예: 땅 구매 직후 건설 → 한 번의
  컷인에서 구매 비트 다음 건설 비트. 카드 하나로 생긴 여러 `MoneyChanged`(모두에게 걷기)는 하나의
  "모두에게 걷기" 이벤트로 묶는다.
- 작은 S 등급 이벤트가 연달아 나오면 두 번째부터는 간략 비트(등장·정리 생략)로 줄인다.

## 5. 소리

| 큐 | 언제 | 만드는 법 |
|---|---|---|
| 코인 빠짐 | 코인 하나가 지갑을 떠날 때 | 짧은 금속음, 음높이 무작위 ±1.5 반음, 동시 발음 최대 6, 25 ms 간격 제한 |
| 코인 쌓임 | 코인 하나가 착지할 때 | 같은 음색에 음높이 사다리 상승(코인마다 +1 반음, 최대 +12) |
| 착-칭 | 마지막 코인 착지 | 기존 `cash-in` |
| 유출 시작 | 첫 코인이 빠질 때 | 기존 `cash-out` |
| 환전 | 금 → 은 쪼개짐 | 높은 반짝임 음 |
| 합계 확정 | 중앙 명판 확정 | 짧은 팡파르(기존 `toll`/`buy`) |

코인 단음은 Web Audio로 합성한다(에셋 생성 키 불필요). 기존 효과음 재생기의 동시 발음 제한을 따른다.

## 6. 속도, 건너뛰기, CPU

- 모든 시간은 `time.ts` 정책을 따른다: 일시정지에 멈추고, 건너뛰기 탭 ×5, 테스트(headless) 0.
- CPU 차례도 같은 이벤트를 보여 준다. 기존 속도 설정(아주 느긋하게 ~ 아주 빠르게)이 이벤트 길이에도
  곱해진다. 현재 CPU 턴 실측 22.6 s(`docs/HANDOFF.md`)가 길어지므로, 결과를 측정해 보고한다.
- 설정 → 애니메이션 "줄이기"에서는 움직임 없이 지갑 숫자 변화, 명판, 소리만 남긴다(시간은 유지).

## 7. 성능 예산

- 동시 DOM 노드: 비행 코인 ≤ 32(풀링), 지갑 기둥 코인 ≤ 4 지갑 × 3 기둥 × 15, 명판 1, 주인공 1.
- 지갑 기둥은 코인 이미지 반복이 아니라 **기둥 하나 = 배경 이미지 반복(`background-repeat`)** 요소
  하나로 그려 노드 수를 줄인다.
- 레이어: 무대 1 + 주인공 1 + 비행 코인 그룹. 게이트 그대로(피크 ≤ 20, 메모리 ≤ 100 MB, Paint ≤ 20/s).
- 이벤트가 끝나면 무대를 화면 밖으로 옮기고 모든 타이머를 정리한다(유휴 0).

## 8. 에셋

- 코인: 기존 아틀라스의 `coin_spin`(금). **은·동 색 변형**을 같은 생성기에 추가하고, 지갑 기둥용
  **코인 옆면 스택 조각**(금·은·동)을 추가한다. 글자·숫자 없음.
- 중앙 금고, 은행, 땅 표지판, 공사 현장(흙더미): 기존 SVG 아이콘 스타일로 새로 그린다.
- 건물·도시 이미지: 기존 아이콘(`src/content/icons`)을 크게 쓴다.

## 9. 구현 순서

1. 에셋: 은·동 코인과 기둥 조각, 금고·은행·땅 표지판·공사 현장 아이콘.
2. 무대 모듈(`src/ui/fx/money/`): 카메라와 비네트, 지갑 더미(자릿수 → 기둥), 비행 코인 풀과 호
   경로, 중앙 명판과 카운터, 코인 소리 스케줄러. 새 파일만 만든다.
3. 연결: `animate.ts`에서 §4 표의 이벤트를 무대로 보낸다. 연속 이벤트 묶기(§4.3). 기존 캔버스
   돈 프리셋은 무대가 대신한다.
4. 검증: 단위 테스트(자릿수 분해, 환전, 묶기), e2e 필름스트립(4 좌석, 1600×1000과 800×450),
   턴 시간 측정, 성능 게이트, 전체 `npm run release:check -- --web`.
5. 비트 조정: 필름스트립을 눈으로 보고 타이밍을 고친다. 실기기 태블릿 확인은 사용자 몫으로 남긴다.

### 10.2 에셋과 크기

- 머니 아틀라스는 **캔버스 VFX 아틀라스와 별개**다. `atlas-color`(512²)·`atlas-mask`(1024²)는 바뀌지 않았고, 머니
  무대만 `money.webp`를 읽는다(디코드 1024×512 = 2 MB).
- `money.webp` 1024×512 78 KB, `money.json` 8 KB, 타일 3장 3.7 KB. FX 비트맵 전체(기존 262 KB 포함) 약 352 KB
  (예산 ≤ 500 KB, `src/content/fx/__tests__/money-atlas.test.ts`가 검사).
- 코인 셀은 48 공칭 px × DPR 2 × 1.2 = 116 px. 비행 코인 표시 크기(1600×1000에서 약 94 CSS px)에서는 약간 확대된다
  (기획 §2 "픽셀이 보여도 허용"). 히어로(금고·은행·표지판·공사 현장)는 같은 생성 함수의 SVG를 **인라인으로** 그려
  화면 60 %에서도 선명하다. 흰 스프라이트(먼지·반짝임)는 `mask-image`로 색을 입힌다.

### 10.3 API

```ts
import { MoneyStage, toll, purchase, build, ... } from '@/ui/fx/money';

const stage = new MoneyStage({
  parent: gameRoot,                       // 무대가 채울 요소(게임 화면 루트)
  boardRect: () => rectOf(board.el),      // 클라이언트 px. 지갑이 보드 축에 선다
  seatRect: (seat) => rectOf(panel(seat)),// (선택) 좌석 패널
  tileRect: (i) => rectOf(board.space(i)),// 정리 비트에서 히어로가 이 칸으로 날아가 합쳐진다
  space: (i) => ({ icon, name, color }),  // 칸의 랜드마크 아이콘 id, 이름, 그룹 색
  camera: (state, tier, ms) => { ... },   // 'in' / 'out': 보드를 물리고 기울이기 (아래 10.5)
  zIndex: 45,                             // 기본 45: 보드·FX 캔버스 위, 메뉴 오버레이(60) 아래
});
const play = toll(stage, { payer, owner, spaceIndex, amount, festival });   // Party = { seat, cash(이벤트 전), color }
await play;                // = play.block: 'settle' 큐에서 풀린다 → 여기서 보드 상태를 바꾼다
play.cue('arrive');        // 'start' | 'depart' | 'arrive' | 'result' | 'settle' | 'done'
play.done;                 // 무대가 내려감(또는 keep으로 다음 장면에 넘김)
stage.newTurn();           // TurnStarted에서: 같은 턴의 같은 종류 반복은 0.7배 길이(터보)
```

장면: `transfer({from,to,via,amount,title})`(from/to = Party | 'bank' | 'pot' | 'center'), `purchase`, `build(level 1–4)`,
`toll`, `takeover`, `collectFromAll({payers:[Party&{amount}], receiver})`, `payAll({payer, receivers})`,
`receive({kind:'salary'|'bonus'|'pot'})`, `pay({kind:'tax'|'donation'|'bail'|'fine'})`,
`bankruptcy({debtor, creditor|null, properties})`. 모든 장면은 `keep`(다음 장면과 한 컷인), `tier`(강제), `title`
(제목 교체)을 받는다. 장면은 큐에 쌓여 하나씩 재생된다.

시간 정책(`time.ts` 표)과의 관계: 장면 시간은 `MoneyClock`만 진행한다. 속도 × 건너뛰기(×5) ÷ (√(게임 속도/2) × 터보)
로 흐르고, 일시정지 중에는 프레임 스텝을 해제했다가(유휴 0) 재개 때 다시 건다. 속도 0(테스트)이면 장면 함수가 즉시
풀리고 아무것도 보이지 않는다(장면 도중 0이 되면 다음 스텝에 끝까지 진행). 앱 설정 "애니메이션 줄이기"에서는 코인
비행·흔들림·스프라이트를 숨기고 시간·숫자·명판·소리는 그대로 둔다. 수동 시계(`setManualClock`/`stepClock`)로
필름스트립이 결정적이다.

### 10.4 엔진 이벤트 → 장면

| 엔진 이벤트 | 장면 | 비고 |
|---|---|---|
| `PropertyBought` (via buy / auction) | `purchase` | 같은 행동에서 `Built`가 이어지면 `keep: true` 후 `build`(한 컷인, §4.3) |
| `Built` (free=false) | `build(level)` | L4는 XL(망치 3회, 광선, 명소 완성). free=true는 코인 없이 기존 연출 유지 권장 |
| `TollPaid` (waived=false) | `toll` | festival → XL + ×2 도장. 짝이 되는 두 `MoneyChanged`(toll)는 장면이 숫자를 대신 보여 주므로 패널 float 생략 |
| `TakenOver` | `takeover` | 테두리 색 전환은 장면 안에서, 보드 소유 변경은 `settle` |
| `PassedStart` / `MoneyChanged(reason:'salary')` | `receive({kind:'salary'})` | |
| `MoneyChanged(reason:'pot', delta>0)` | `receive({kind:'pot'})` | 출발 정지 보너스 |
| `MoneyChanged(reason:'tax'|'donation'|'bail')` | `pay({kind})` | donation은 팟으로, 이어지는 `PotChanged`는 장면 뒤 렌더 |
| 카드로 생긴 `MoneyChanged(reason:'card')` 여러 개 | 받는 사람 1 + 내는 사람 여럿 → `collectFromAll`, 반대 → `payAll`, 은행에서 → `receive({kind:'bonus'})`, 은행으로 → `pay({kind:'fine'})` | §4.3: 한 카드의 변화는 묶어서 한 장면 |
| `BuildingSold` / `PropertySold` (`reason:'sale'`) | `transfer({from:'bank', to: 나, amount, title: t('m.sale')})` | §4.2 매각(건물 해체 히어로)은 아직 없음 |
| `Bankrupt` (+ 뒤따르는 `PropertyTransferred`, `MoneyChanged(reason:'bankruptcy')`) | `bankruptcy` | 채권자 없음(은행) → `creditor: null` |

### 10.5 연결 단계가 해 줄 것

1. **무대 생성**: 게임 화면 마운트 때 `new MoneyStage(host)` 한 번, 언마운트 때 `destroy()`. `loadMoneyAtlas()`는
   생성자가 미리 부른다(실패해도 코인은 CSS 원판으로 대체).
2. **사각형 공급자**: `boardRect`, `tileRect`, `space`는 꼭 필요하다. 장면 시작 때 한 번씩만 읽는다(강제 레이아웃 1회).
3. **카메라 콜백**: 'in'에서 보드를 0.92배로 물리고 'out'에서 되돌린다(장면 시계에 맞추려면 `stage.tween(ms, fn)` 사용,
   데모 참고). **측정 결과 보드에 `rotateX` 3D 기울임을 걸면 레이어가 3–4개 늘었다**(모의 보드, §10.6). 기본은
   2D(scale + 약간의 translateY)로 하고, 3D 기울임은 실제 보드에서 레이어 수를 재 보고 결정한다.
4. **보드 상태 반영 시점**: `await play`(= 'settle')에서 소유 색·건물 레벨·패널 금액을 바꾼다. 장면이 지갑 숫자를
   보여 주므로 그동안 패널 float/카운트업은 생략한다. `play.done`은 기다리지 않아도 된다(다음 장면은 큐가 순서를 지킨다).
5. **현금 값**: Party의 `cash`는 **이벤트 전 잔액**(vs: 시퀀서의 view state). 장면이 끝나면 지갑 숫자 = 이벤트 후 잔액.
6. **턴 경계**: `TurnStarted`에서 `stage.newTurn()`.
7. **건너뛰기**: 기존 skip(×5)이 그대로 적용된다(점프 아님). 일시정지(`setHeld`)도 그대로.
8. **기존 돈 프리셋**: 연결 후 같은 이벤트의 캔버스 돈 프리셋(tollPay, coinIn 등)과 패널 float을 끈다(이중 표시 방지).

### 10.7 필름스트립 (`node scripts/fx/money-strips.mjs`, `docs/assets/money-strips/*.png`)

모든 장면 × S 좌석(1600×1000), 통행료·구매·명소·모두에게 걷기 × E/N/W, 통행료·구매·호텔·걷기·월급·세금 × S/E
(800×450). 2틱마다 한 장, 라벨 = 장면 프레임과 비행 코인 수. 보고 나서 고친 것:

- 지갑·코인이 너무 작아 "어디서 나와 어디로 가는지"가 약했다 → 코인 폭 짧은 변의 5.8 % → 7.5 %, 비행 코인 1.25배,
  히어로 52 % → 60 %, 비네트/딤을 진하게(등급별 0.78–0.97).
- 명판 금액이 실제 금액보다 작게 끝났다(카운트 도중 값에 더함) → 명판 목표값 누적. 받는 사람 숫자가 장면 끝까지
  안 올라간 경우(이전 장면의 쓰기 시각이 남음) → 장면마다 초기화, 카운트업을 첫 착지 기준 한 번의 ease-out으로.
- 통행료·인수·모두에게 걷기가 3.3–4 s로 길었다 → 리서치 프레임에 맞춰 홉/이동/홀드를 줄여 settle 66–88 f.
- 명판이 착지 코인·지갑과 겹쳤다(특히 800×450) → 명판을 히어로의 "그 좌석 기준 앞-오른쪽 모서리"로. 네 좌석 합계
  명판은 서로 다른 네 모서리에 놓여 겹치지 않는다.
- 별 모양 버스트가 플레이어 색 별 덩어리로 보였다 → 코인 반짝 터짐 + 플레이어 색 반짝임으로 교체. 버스트 첫 프레임의
  회색 원반 → 2프레임 섬광으로.
- 월급 코인이 한 줄로만 떨어졌다 → 은행에서 부채꼴로 솟았다가 좌우 호로 떨어지는 분수.
- 인수 도장이 장면이 끝난 뒤에도 남았다 → 정리 비트에서 함께 사라짐. 카메라 'out'이 무대보다 늦게 끝나 보드가
  1.5° 기운 채 남았다 → 같은 길이로.

### 10.8 적용한 결정 (코디네이터, 리서치 06 정합)

금·은·동 = 1,000/100/10만(보석 단계 없음), 금 기둥만 로그 압축(n ≤ 5 그대로, 이후 5 + ⌊log2(n−4)⌋, 최대 15 + `+`),
숫자와 더미는 코인 출발/착지에 맞춰 바뀜, 카운트업 ease-out cubic 500 + 300·log10(1 + 금액/10) ms(≤ 15 Hz 쓰기),
베지어 제어점 0.15–0.25 × 거리, 높이 = 스케일 1 + 0.25·sin, 스폰 홉 후 끝에서 빨려듦, 스트림당 그림자 1개, 풀 16·
이동당 ≤ 12, 지불 = 하강 피치 + 툭(챠링 없음) / 수령 = 펜타토닉 래더 + 챠링(≥ 150 ms 간격), 클링크 4음색 라운드로빈
±1 반음, 코인 버스 6보이스, 햅틱 첫 착지 light · 3번째마다 tick · 마지막 medium · 도장 heavy(≤ 10/s), 모두에게 걷기
합계 명판 4방향, 건너뛰기 = ×5, 같은 턴 반복 0.7배.

### 10.9 남은 일 / 미확인

## 11. 연결 결과 (2026-10-05, §9 3–5단계)

§10의 무대 모듈을 게임에 연결했다. 모든 구매·지출·수입이 전체 화면 컷인으로 재생되고, 컷인이 손을 놓는
순간(`settle` 큐)에 보드·패널 상태가 바뀐다. 기존 캔버스 돈 프리셋(plotClaim, buildSeq, landmarkReveal,
tollPay, takeoverStamp, passStart, billRain, coinIn, bankruptcy)·패널 금액 float·통행료 카드는 이 이벤트들에
대해 더 이상 재생되지 않는다(이중 코인·이중 소리 없음). 캔버스는 그 뒤의 색 그룹 완성(groupChain)과 승리만 맡는다.

### 11.2 묶기와 순서 (`src/ui/fx/moneymap.ts`)

- `planMoney(events)`는 순수 함수다. 한 `reduce` 배치의 돈 이벤트를 위 표의 그룹으로 묶고, 그룹의 첫 이벤트에서
  장면을 시작한다(그때 시퀀서의 view state 현금 = 이벤트 전 잔액). 장면이 `settle`에 이르면 그룹의 모든 이벤트 상태를
  `applyMoneyState`로 적용하고 렌더한다. `REASON_SCENES`는 `MoneyReason`마다 가능한 장면을 적은 완전한 표다.
- §4.3 한 컷인: 다음 그룹이 곧바로 이어지면(사이에 `PotChanged`·`Demolished`·`DebtSettled`·`CardUsed`만) 앞 장면을
  `keep`으로 끝내 무대를 내리지 않는다. 예: 출발 통과 월급 → 세무서 세금, 빚 매각 → 밀린 통행료. 지금 규칙에서
  땅 구매 뒤 건설은 건설 프롬프트(별도 행동)를 거치므로 두 컷인이다(같은 배치에 오면 한 컷인으로 묶인다).
  `keep` 뒤에 이어질 장면이 없으면 `releaseKept()`가 무대를 내린다.
- 같은 턴에 같은 종류가 다시 나오면 0.7배 길이(`stage.newTurn()`은 `TurnStarted`에서).
- 한 번에 하나: 돈이 아닌 다음 이벤트(턴 끝, 다음 턴 배너, 토스트, 카드 …)는 컷인이 완전히 내려간 뒤 재생된다.
  배치가 끝나면 프롬프트도 무대가 내려간 뒤에 나온다.
- 끊긴 컷인(라운드 1, `docs/REVIEW-2026-10-06.md`): 화면 크기·방향이 바뀌거나(`GameView.stopFx`) 화면을 떠나면(`destroy`)
  `MoneyStage.abort()`가 장면을 그 자리에서 끝낸다. 장면 시계를 버릴 때 남은 스텝을 "시간 끝"으로 한 번 돌려 트윈·코인·
  카운트를 끝내고, 시계 없이 날린 코인은 바로 착지한다. 남은 장면 본문은 무대가 내려간 채 소리 없이 끝까지 돌아 `settle`·
  done이 풀리고 다음 장면이 재생된다(전에는 여기서 게임이 멈췄다).
- CPU: CPU 손이 버튼을 누르고 **손을 떼고 나간 뒤**(`CpuHand.whenGone()`) 컷인이 올라온다. 매 프레임 샘플링한
  e2e에서 손과 무대가 함께 보인 프레임 0, 순서 손 → 무대.

### 11.5 시간

모든 장면은 `MoneyClock`(30 Hz `onFrame`, `time.ts` 정책)으로만 흐른다. e2e로 확인한 것(`e2e/money-events.spec.ts`):

- 일시정지: 장면 시계가 멈춘다(1.5 s 동안 t 그대로, 무대는 떠 있음). 계속하기를 누르면 이어서 끝난다.
- 건너뛰기(보드 탭): ×5. 통행료 컷인 2.38 s → 0.70 s.
- headless(속도 0): 무대가 한 번도 올라오지 않고 상태가 즉시 적용된다.
- 앱 설정 "애니메이션 줄이기": 시간은 그대로(2.30 s), 날아가는 코인 0개, 숫자·명판·소리는 그대로, 지갑 = 엔진 현금.
- 게임 속도: 장면 길이 × √(속도/2) (§10.3).

장면 길이는 §12(비트 확장)로 바뀌었다: 모든 장면이 화면에 3.1 s 이상, 보통 3.7–5.3 s. §12.4(2026-10-06) 이후 4.1 s 이상,
보통 4.7–6.5 s.

턴 시간 (`e2e/pacing.spec.ts`, 이 컨테이너, 네 환경 × 2회):

| | 전 (연결 전, 74f15b6) | 후 | 차이 |
|---|---|---|---|
| 사람 턴: 굴림 → 결정 | 6.12–6.18 s | 6.12–6.19 s | 0 (이 구간엔 돈 이벤트 없음) |

40 % 기준에 한참 못 미쳐 S/M 등급을 줄이지 않았다. 컷인이 기존 캔버스 프리셋 + `BEAT.change` 대기 + 통행료 카드를
대신하므로 늘어난 시간이 작다.

## 12. 비트와 12원칙 적용 (2026-10-05, 제품 책임자 피드백 반영)

중간 빌드(`MoneyPoly-0.1.0-20261005-2131-debug`)를 본 제품 책임자 피드백: **컷인이 너무 짧게 지나가서 눈이 따라가지
못한다.** 모든 돈 이벤트는 화면에 **3초 이상** 머물고, 사람이 읽을 수 있게 움직이며, 끝난 뒤 **정지 화면이 1초 이상**
남아 상황을 읽을 수 있어야 한다. 픽사 12원칙을 적용하고 비트를 넉넉히 둔다. 그래서 모든 장면을 "포즈 → 포즈"로 다시 짰다
(`src/ui/fx/money/scenes.ts` `BEATS_F`, `finish()`).

### 12.1 비트 문법 (보통 속도, 게임 속도 2, 30 fps 프레임)

아래 프레임은 **장면 시간**이다. 2026-10-06부터 화면에서는 `EVENT_EXTEND`(§12.4)만큼 더 길다: 움직이는 비트는
비례해서 느려지고(+0.5 s), 정지는 +0.5 s(45 f).

| 비트 | 길이 | 무엇이 보이나 |
|---|---|---|
| 등장 / 예비 동작 | ≥ 18 f (0.6 s) | 비네트가 깔리고 주인공이 작게 뒤로 누운 채 들어와 살짝 넘쳤다가 **자리 잡음**(10 f). 지갑이 솟아 자리 잡음. 나갈 코인이 **떠오르며 반짝임**(8 f, `wallet.lift`) — 그 뒤에 첫 코인이 떠난다 |
| 동작 | ≥ 1.2 s | 코인이 하나씩(간격 2–3 f) **천천히 떠서 천천히 내려앉는 호**(홉 6 f + 비행 13–15 f, cos 이징; 직선·등속 없음)로 날아간다. 내는 사람 숫자는 코인이 떠날 때, 받는 사람 숫자는 **코인이 닿을 때** 바뀐다. 모아서 넘기는 장면(통행료·걷기·주기·중앙 경유)은 모인 합계 명판이 **모인 뒤에** 뜨고(9 f, 오버슈트), 주인공이 떨리는 한 박자(4–5 f, 예비 동작) 뒤 받는 사람에게 터져 나간다 |
| 결과 | ≥ 15 f (0.5 s) | 결과 포즈: 건물은 부지가 **웅크렸다가**(4 f) 높이의 약 18 % **넘게 솟고** 착지하며 **찌그러졌다 돌아옴**(10 + 6 f). 깃발은 박히며 넘쳤다가 찌그러짐. 금고가 열림, 세무서가 쿵 하고 눌렸다 튐. **그 다음에** 명판이 작게 시작해 넘쳤다 자리 잡으며(9 f) 최종 금액까지 센다 |
| 정지 | ≥ 30 f (1.0 s) + 0.5 s (§12.4) | 아무것도 움직이지 않는다. 주인공 가장자리의 작은 반짝임(14 f마다)과 구매 깃발의 느린 흔들림(±4°)만. 명판·지갑 최종 숫자·주인공이 다 보인다. 장면 전체가 3.1 s보다 짧아질 것 같으면 이 정지가 늘어난다 |
| 퇴장 | 9 f (0.3 s) | 주인공이 보드의 그 칸으로 날아가 합쳐지고, 지갑이 가라앉고, 무대가 사라진다(동시에). 보드 상태는 퇴장이 시작될 때(`settle`) 바뀐다 |

- **하한**: `MIN_SCENE_MS = 3100 + 1000 = 4100` ms(무대가 올라와서 내려갈 때까지; §12.4 이전 3100). 같은 턴의 반복
  이벤트(0.7배)도 정지 비트가 늘어나 이 아래로 내려가지 않는다(`finish()`: 정지 = max(1 s × factor + 0.5 s, 4.1 s −
  지금까지 − 퇴장)). S 등급 "간략" 장면은 코인·파티클 수만 줄이고 시간은 줄이지 않는다.
- 시간 정책은 그대로다: 게임 속도가 길이를 늘이고 줄이며(√(속도/2)), 탭 건너뛰기 ×5, 일시정지에 멈춤, headless 0.

장면별 길이는 §12.4의 표(EVENT_EXTEND 전후)를 본다.

두 번 나르는 장면(지불자 → 중앙 → 받는 사람)은 결과·정지 비트를 다 지키면 4.6–5.3 s가 된다. 첫 구간 코인 4–6개,
두 번째 구간은 1 f 간격으로 터지듯 나가게 줄여서 이 길이에 맞췄다.

### 12.4 이벤트 연출 +1초 (2026-10-06, 제품 책임자: "여전히 너무 빠르다")

요청: 모든 이벤트 연출을 합계 1초 더 길게. 0.5초는 동작 자체를 더 길게, 0.5초는 마지막 장면을 더 오래 보여 주기.
한 곳에서 조절한다: `src/ui/fx/time.ts`의 `EVENT_EXTEND = { motionMs: 500, holdMs: 500 }`(게임 속도 2 기준 ms,
시간 정책 표 맨 위에 설명). 컷인에서는:

- **동작 +0.5 s**: 장면 시계가 움직이는 비트 동안 느리게 돈다(`MoneyClock.stretch`). 처음부터
  `MOTION_STRETCH = 1 + 500 ms / MOTION_REF_F`(= 1.15배, `MOTION_REF_F = 100` f = 전형적인 컷인의 동작 길이)로
  등장·예비 동작·코인 비행·지갑 출렁임·숫자 카운트·코인 소리까지 같은 비율로 느려지고, `finish()`가 결과 → 명판 → 퇴장
  비트에서 남은 만큼을 채워 동작이 정확히 +0.5 s가 된다(`trueUp`; 짧은 컷인은 그 비트가 조금 더 느리고, 아주 긴 컷인 —
  축제 통행료 — 은 +0.5 s를 조금 넘는다). 멈춤을 끼워 넣지 않는다: 같은 포즈가 더 천천히 온다. 늘어난 비트는 30 Hz의
  가장 가까운 프레임에서 끝난다(`MoneyClock.snap`), 그래서 이어지는 비트가 한 프레임씩 밀리지 않는다.
- **정지 +0.5 s**: 정지 비트 = 1.0 s + 0.5 s = 1.5 s(45 f, 정상 속도로 흐름). 하한 `MIN_SCENE_MS` 4.1 s.
- 게임 속도(√(속도/2))·건너뛰기 ×5·일시정지·headless 0·애니메이션 줄이기(시간 유지)는 그대로 곱해진다. CPU 턴도 같다.

18aa79c; 괄호 = 같은 턴 반복 0.7배). 테스트는 "전 + 1000 ms ± 3 f"와 정지 45 f를 본다.

## 13. 기기별 연출 해상도와 3D (2026-10-05)

제품 책임자 요구: 3D 기울임과 보드 카메라를 쓸 수 있게, 머니 무대를 기기에 맞는 해상도로 그린다(픽셀이 보여도 괜찮음).
레이어 메모리는 기기 픽셀에 비례한다(w × h × DPR² × 4 B). 그래서 무대 레이어를 렌더 배율 s로 그리면 s²만 쓴다. 메모리
예산도 등급마다 다르다: 큰 기기는 GPU 예산이 크다. 코드: `src/ui/fx/money/render.ts`.

### 13.1 등급

| 등급 | 렌더 배율 | 3D 기울임 + 보드 카메라 | 컷인 중 피크 레이어 메모리 예산 |
|---|---|---|---|
| high | 1.0 | 켬 | 250 MB |
| mid | 0.75 | 3D 기울임만, 기기 픽셀 ≤ 4.1 M일 때(1280×800 DPR 2 이하). 보드 카메라는 끔(2026-10-06, 피크 레이어 21 → 19, `docs/PERFORMANCE.md` "라운드 2") | 150 MB |
| low | 0.5 | 끔 (2D) | 100 MB |

자동 선택(`pickTier`): deviceMemory(GB, 브라우저가 0.25–8로 반올림; 8은 "8 이상"; 없으면 4로 봄)와 기기 픽셀
P = innerWidth × innerHeight × DPR².

- high: deviceMemory ≥ 8, DPR ≥ 2(DPR < 2 화면은 보급형으로 봄), P ≤ 7.0 M (1600×1000 DPR 2 = 6.4 M)
- mid: deviceMemory ≥ 4이고 P ≤ 7.0 M, 또는 deviceMemory ≥ 8이고 P ≤ 17 M (2560×1600 DPR 2 = 16.4 M)
- low: 그 밖(deviceMemory ≤ 2, 4 GB 기기의 아주 큰 화면)

예: 1600×1000 DPR 2 → 8 GB면 high, 4 GB면 mid, 2 GB면 low. 1280×800 DPR 1.5 → mid(4–8 GB) / low(≤ 2 GB).
2560×1600 DPR 2 → 8 GB면 mid, 4 GB면 low. 크기·방향이 바뀌면 다시 고른다. 이 컨테이너의 헤드리스 Chromium은
deviceMemory 8을 보고한다.

설정 → **연출 해상도**(자동/높음/낮음, 높음 = high, 낮음 = low)와 **3D 연출**(자동/켬/끔)이 자동을 덮어쓴다. 바로 적용되고
(진행 중인 컷인은 자기 설정으로 끝난다), 개발 스위치 `?dev=1&mres=high|mid|low`, `m3d=1|0`, `mcam=off|2d|3d`도 남아 있다.

### 13.2 어떻게 낮은 해상도로 그리나 (측정)

- 무대 안쪽 `.ms-scaler`를 화면의 s배 크기로 배치하고 `transform: scale(1/s)`로 키운다. `will-change: transform`을 준다.
- **처음 시도(배치하고 바로 키우기)는 효과가 없었다.** Chromium의 레이어 스냅샷(트레이스 `cc::PictureLayerImpl`
  `raster_scales.contents_scale`)으로 재 보니 800×500으로 배치한 무대를 배율 2로 래스터해서 1600×1000 픽셀(전체 해상도)
  그대로였다(타일 7.0 MB, 문서 레이어 7.3 MB와 같음). 그리고 `npm run perf`의 메모리 계산(레이어 경계 × DPR²)은 이걸
  1/4로 잘못 셌을 것이다.
- Chromium은 `will-change: transform` 레이어의 래스터 배율을 **처음 래스터할 때** 정하고 유지한다. 그래서 무대를 처음
  3프레임(`RASTER_HOLD_F`) 동안 작은 크기 그대로(불투명도 0.01) 보여서 그 크기로 래스터되게 한 뒤에 1/s로 키운다.
  재 보니 low 무대 800×500 @1(= 800×500 × DPR, 타일 2.0–2.5 MB), mid 1200×750 @1(4.0 MB). 3D일 때 기울어진
  주인공 위의 지갑·코인 레이어(`.ms-top`)도 같은 방식으로 붙잡아야 했다(처음엔 아무것도 그리지 않아 나중에 1.33배로
  래스터됐다 → 2 px짜리 거의 투명한 점을 둬서 붙잡음). 기울어진 주인공 레이어는 3D 변환이라 처음부터 배치 크기로
  래스터됐다(600×708 @1).
- 같은 수치를 언제든 다시 재는 스크립트: `npx vite build && node scripts/fx/money-raster.mjs [--viewport 1280x800 --dpr 1.5]`.
- 레이아웃은 등급과 무관하게 같다: e2e가 high와 low에서 같은 프레임의 주인공·지갑·명판 상자가 4 px 단위 ±1 안에서 같은지
  본다. 스크린샷 `e2e/__screenshots__/money-tier-{high,low}-1600x1000.png`. 헤드리스 스크린샷은 다시 그려서 찍기 때문에
  픽셀 차이는 사진에 나타나지 않는다(실제 화면 해상도 차이는 위 트레이스로만 확인).

### 13.4 실행 중 안전장치

컷인마다 30 Hz 장면 시계로 프레임 상태를 잰다(`MoneyHealth`, `vfx/director.ts` AdaptiveQuality와 같은 생각): 장면 스텝의 JS
시간 p95 > 8 ms이거나 스텝 사이 간격 > 50 ms가 25 % 넘으면 그 컷인은 "나쁨". **두 번 연속 나쁨 → 한 등급 내림**(배율과 3D),
앱 세션 동안 유지. **네 번 연속 좋음 → 한 등급 올림**(자동 등급보다 위로는 안 감). 15 스텝 미만(건너뛰기, 짧은 컷인)은
판정하지 않는다. 일시정지 후 첫 스텝은 간격을 재지 않는다. 설정이 자동일 때만 작동하고, 바뀌면 개발 모드에서
`[money] render tier high → mid (…)`를 남긴다(`window.__lotAndRoll.money().log`). 위 측정(4× 스로틀)에서 자동 high는 컷인
판정 ok, ok, bad로 내려가지 않았다.

`npm run perf`의 레이어 메모리 게이트는 이제 그 실행의 자동 등급 예산을 쓴다(표에 등급을 적는다).
