# 09 — sprite-gen 리서치: 캐릭터·연출 애니메이션 보강에 쓸 수 있나

2026-10-07. 오너가 https://github.com/aldegad/sprite-gen (Apache-2.0, v2.38.0, 커밋 f7cb0db 기준)을 보여 주며
"이 스킬로 캐릭터 애니메이션이나 다른 연출을 더 좋게 만들 수 있는지 조사하고, 재미와 완성도에 도움이 되면
쓰라"고 했다. 필수 과제는 아니다.

## 0. 결론

- **지금 바로 쓸 수 있는 것은 하나**: 생성 모델 없이 도는 결정론 후처리 **Breathe**(정지 그림 한 장 → 머리는 그대로
  두고 몸통만 숨쉬는 스쿼시&스트레치 프레임). 우리 딜러 그림(320px, 부드러운 3D 렌더)에 걸어 보니 깨끗하게 나온다
  (§2). 이것으로 **건물 팔 때 우는 딜러의 흐느낌**을 CSS 확대·축소(머리까지 늘어남) 대신 진짜 어깨 들썩임 프레임으로
  바꾼다(§4). 쓰는 조건이 맞는 자리가 이곳뿐인 이유는 §3.
- **큰 효과는 생성 파이프라인에 있다**: 정지 한 장을 Grok Imagine 영상으로 움직여 투명 루프(WebP)로 잘라 주는 B
  파이프라인. 딜러의 "말하는 몸짓"과 "기다리는 자세"를 진짜 움직임으로 바꿀 수 있다. 그러나 **Codex(ChatGPT) 로그인
  또는 Grok 로그인/xAI 키**가 있는 PC에서만 돈다. 이 컨테이너에는 없다. 주말 작업 후보로 정리했다(§5).
- **안 맞는 것**: 격자 보존·픽셀아트 전제의 기능들(Backbone Lattice, 팔레트 스왑 `recolor`), 걷기·뛰기 루프 수리(RIFE,
  Vulkan GPU 필요), 장면 합성. 우리 말(토큰)·건물·동전은 SVG → 아틀라스 파이프라인(`scripts/fx/bake.mjs`)이 이미 있고,
  보드 위 작은 아이콘이라 영상 루프로 바꿀 이유가 약하다.

## 1. sprite-gen이 무엇인가

- Codex/Claude 스킬 + Python CLI(Pillow, NumPy). 그림 한 장을 넣으면 (A) 이미지 모델로 상태별 행을 생성해 크로마를
  벗기고 아틀라스(`manifest.json.frame_layout`)로 굽거나, (B) 영상 모델(Grok Imagine)로 움직여 진짜 주기에서 잘라
  투명 루프를 만든다. 큐레이션 웹뷰에서 고르고 손보고 숨쉬기(Breathe)를 얹는다.
- 생성과 무관하게 혼자 도는 도구: `cutout`(단색 배경 제거, 소프트 알파 언믹스), `slice-sheet`, `unpack-atlas`,
  `shadow`(발 기준 투영 그림자), `background-tile`, `inspect-motion`, 그리고 compose 단계의 **Breathe**.
- 접근 전제: `gen`은 codex(ChatGPT 구독) / grok(SuperGrok 구독 또는 `XAI_API_KEY`) / openai(건별 과금, 명시해야만).
  `video*`는 Grok 로그인(`grok login`, `~/.grok/auth.json`) 또는 `XAI_API_KEY`. `video-set`의 걷기·뛰기 수리는
  RIFE(rife-ncnn-vulkan). 이 컨테이너: Python venv 설치는 됐고(`pip install -e`), 로그인·키·GPU는 없다.

## 2. 실험: Breathe를 딜러 그림에 (이 컨테이너, 오프라인)

입력 `public/dealer/idle.webp`, `sad.webp`(320×320, 알파). `bake_breathe_sequence([still]*6, {depth, breaths: 1, lag: 0.1})`.

| 항목 | idle (depth 0.06) | sad (depth 0.08) |
|---|---|---|
| 해부 검출 | 목 병목 147행, 얼굴 147–200행, 몸통 축 x=97 | 목 130행, 얼굴 132–205행, 축 x=93 |
| 머리 윗선(행) 위상별 | 18, 28, 29, 24, 18, 13 | 25, 38, 39, 33, 24, 17 |
| 어깨 폭(열) 위상별 | 61–255 → 56–262 | 71–273 → 52–273 |
| 머리 내부 변형 | 없음(통째로 위아래 이동만) | 없음 |
| 눈에 보이는 결함 | 없음. 끊김·찢김 없음, 외곽선 유지 | 없음 |

- 부드러운 3D 그림에서도 깨끗하다: 가로는 정수 열 사상(단조)이라 접히지 않고, 세로는 행 복제·삭제라 번짐이 없다.
  머리는 비트 동일하게 유지되고 **위아래로만 최대 14px(320 기준) 움직인다**. 그래서 머리 위에 얹는 것(눈물)은 위상별
  머리 이동량만큼 같이 옮겨야 한다.
- 6위상 시트 하나 = 1920×320. 디코드 메모리 약 2.4 MB. 파일은 WebP 수십 KB.
- 결과 시트: `scratchpad/breathe-out/{idle,sad}-sheet.png`(세션 임시). 제품에 들어가는 것은 §4의 `sad-sob.webp`.

## 3. 우리 게임의 제약과 맞춰 보기

| 후보 | 효과 | 막는 것 | 판정 |
|---|---|---|---|
| 딜러 **대기 숨쉬기** 루프 | 살아 있어 보임 | **유휴 부하 0 정책**(게이트 B): 대기 중 프레임 교체는 매번 페인트. 딜러가 "다음 이벤트까지 표정 유지"로 바뀐 이유가 바로 이것 | 하지 않음 |
| 딜러 **말할 때** 몸 숨쉬기 | 입만 움직이는 지금보다 자연스러움 | 입 프레임(talk-a/b)과 표정 13장마다 6위상 시트 → 15장 × 2.4 MB 디코드. 말할 때마다 시트 전환, 삼성 WebView 메모리 미검증 | 보류. §5에서 영상 루프로 대체하는 편이 낫다 |
| **판매 컷인 흐느낌** | CSS scale 흐느낌은 머리까지 늘어남 → 진짜 어깨 들썩임, 머리 고정 | 컷인 중에는 페인트 허용. 시트 1장(2.4 MB)만 컷인 동안 | **적용**(§4) |
| 토큰(말) 걷기·점프 루프 | 말이 살아 움직임 | 영상 생성 필요(로그인), RIFE(GPU), 말 아트가 평면 SVG 아이콘이라 스타일 충돌 | 하지 않음 |
| 건물·토큰 투영 그림자 `shadow` | 바닥에 붙은 느낌 | 건물은 이미 흰 테두리+그림자, 방향별·단계별 PNG가 늘어남(아틀라스 메모리) | 하지 않음 |
| 딜러 그림 크로마 제거를 `cutout`으로 | 머리카락 가장자리 품질 | 지금 ffmpeg colorkey 결과에 보고된 문제 없음. 원본 캐시는 오너 PC에만 | 주말에 재생성할 때 비교만 |

## 4. 적용: 판매 컷인의 흐느낌 (`sell` 장면)

- `scripts/dealer/bake-sob.py`가 `sad.webp` → 6위상 시트 `public/dealer/sad-sob.webp` + 위상별 머리 이동량(`headDy`)을
  굽는다. 굽는 데만 Python/sprite-gen이 필요하고 **앱 빌드는 결과 파일만 쓴다**(커밋됨).
- 장면은 시트를 `background-position`으로 넘기며(캔버스 없음, Android 경로 그대로) 장면 시계(30 Hz, 일시정지·건너뛰기·
  수동 필름 시계 호환)에서 위상을 고른다. 흐느낄 때는 빠른 주기(한 바퀴 ≈ 0.5초), 그 사이와 정지 장면에서는 느린 숨
  (≈ 1.5초). 눈물 층은 `headDy[위상]`만큼 같이 내려가 눈꺼풀에 붙어 있다. 동작 줄이기: 0위상 고정.
- 상세와 검증은 `docs/MONEY-EVENTS.md` §14, 구현 메모는 아래 §6.

## 5. 주말 후보 (생성 모델 로그인이 있는 PC)

우선순위 순. 하나도 필수가 아니다. 모두 오너 PC에서 `sprite-gen` 설치 후.

1. **딜러 "말하는 몸짓" 루프 (B 파이프라인)**: `idle.webp`를 바탕으로 2–3초 영상 → 투명 WebP 루프. 지금의 입 2장 교대
   대신 고개·어깨·손이 살짝 움직이는 루프를 **말하는 동안만** 재생(유휴 0 유지). 애니메이션 WebP 한 장을 `<img>`로
   바꿔 끼우면 되므로 코드 변경이 작다. 확인할 것: 삼성 WebView의 애니메이션 WebP 재생, 디코드 메모리(루프 2초 × 12fps
   × 320px ≈ 10 MB), 딜러 그림과 영상 프레임의 정체성 유지.
   ```sh
   sprite-gen video-canvas --base idle.png --state idle            # 정사각 캔버스
   sprite-gen video --image <canvas.png> --prompt "<말하는 몸짓 프롬프트>" --duration 3 --aspect-ratio 1:1
   sprite-gen video-frames --video <clip.mp4> ...; sprite-gen video-loop ...   # → .webp 루프 + strip.json
   ```
   (`video-set --states idle`는 "두 발 고정, 가슴·어깨 정착"을 요구하므로 말하는 몸짓은 `video --prompt`로 직접.)
2. **표정 전환 보간**: `interpolate`는 생성형(codex/grok)이라 로그인 필요. idle ↔ cheer 사이 중간 포즈 1장씩 만들면
   표정이 "탁" 바뀌는 것이 줄어든다. 효과 대비 비용은 1번보다 낮다.
3. **딜러 그림 재생성 시 `cutout`**: 지금 파이프라인(`scripts/dealer/gen-sprites.mjs`, Gemini + ffmpeg colorkey) 결과와
   머리카락 가장자리를 비교. 차이가 없으면 그대로 둔다.

하지 않기로 한 것: 토큰 영상 루프(스타일·GPU), 대기 숨쉬기(정책), 장면 합성(`scene-*`, 우리 보드와 무관).

## 6. 구현 메모

판매 컷인 흐느낌 적용(2026-10-07). 상세: `docs/MONEY-EVENTS.md` §14.5.

- **굽기**: `scripts/dealer/bake-sob.py`(venv + `pip install "git+https://github.com/aldegad/sprite-gen@f7cb0db"`). 쓰는 API는
  `recommended_breathe_frames(cfg)`(= 6)와 `bake_breathe_sequence([정지 그림] * 6, cfg)`뿐. 같은 입력이면 같은 바이트(두 번
  구워 SHA 같음). 결과 `public/dealer/sad-sob.webp`(1920×320, q92 + 무손실 알파, 94,020 B; 무손실은 117,372 B)와
  `src/content/fx/sob-sheet.ts`(`headDy`)를 커밋한다.
- **depth 0.08**(0.10 대신): 머리 이동 22 px(−13…+9). 0.10은 28 px에 눌린 프레임에서 재킷 아랫단이 불룩해지고 가방끈 사이가
  벌어진다.
- **headDy 기준은 정지 그림**: `sad.webp`는 사각형 전체에 알파 1의 자홍 안개(크로마키 잔여)가 있어서 "알파 > 0 첫 행"이 0이다.
  §2 표의 머리 윗선(25, 38, …)은 구운 프레임의 경계 상자 윗선이고, 정지 그림의 단단한 윗선(알파 ≥ 128, sprite-gen
  `solid_alpha_bbox`와 같은 기준)은 30이다. lag 0.1 때문에 0위상도 정지 그림과 같지 않다(머리 5 px 위). 눈꺼풀 좌표
  (`SAD_EYES`)가 정지 그림에서 잰 것이므로 headDy = 정지 그림 기준 [−5, 8, 9, 3, −6, −13](0위상 기준 [0, 13, 14, 8, −1, −8]이
  아님). 최대 이동은 위로 13 px(스프라이트의 4.1 %): e2e의 눈물 ±3 % 검사가 이 위상을 반드시 거치게 했다.
- **강체 구간**: 행 30–220(모자부터 어깨·가방끈 윗부분까지)이 모든 위상에서 비트 단위로 같고 위아래로만 옮겨진다(스크립트가
  검사). 그래서 어깨는 머리와 함께 오르내리고 모양이 바뀌는 것은 그 아래 몸통이다. `rigid_row`는 쓰지 않았다.
- **분홍 테두리**: 원본의 반투명 가장자리 픽셀이 자홍색을 머금고 있어서 워프가 가장자리 열을 복제한 곳(소매)에 분홍 테두리가
  보였다. 굽기 전에 알파 8–249 픽셀의 색만 가까운 불투명 픽셀 색으로 바꾼다. 알파 1–7 안개를 지우면 워프의 외곽선 다듬기
  (`_thin_outline_1px`)가 행 끝을 실제 외곽선으로 보고 머리 행까지 건드려서(강체 검사 실패) 안개는 둔다.
- **재생**: 장면 시계의 스텝 하나가 `phaseAt(t)`(순수, `src/ui/fx/money/sob.ts`)로 위상을 골라 바뀔 때만
  `background-position`과 눈물 상자의 `translateY`를 쓴다. 느린 숨 45 f, 흐느낌 15 f(예비 동작 2주기, 결과 1주기). CSS 크기
  훌쩍임(`sniffle`)은 지웠다. 비트 길이는 그대로(단위 측정 큐 프레임 동일).
