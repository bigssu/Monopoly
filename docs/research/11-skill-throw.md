# 11 — 손맛 던지기: 누르는 타이밍 × 미는 길이로 작은 수·큰 수 노리기

2026-10-08. 오너 요청: "주사위를 누르고 흔드는 타이밍과 던지는 힘 두 가지를 조합해, 낮은 수나 높은 수가 나올
확률을 올리는 시스템. 정확한 타이밍에 누르기를 멈추고 살짝 밀면 가장 낮은 수가 나올 확률이 80%까지, 세게 밀면 가장
높은 수 쪽으로. 너무 복잡한지, 더 좋은 방법이 있는지 제안하고, 납득할 수 있는 아주 명료한 UI로."
함께 들어가는 규칙: `docs/research/10-strategy-depth.md`의 추천 패키지(규칙 버전 3).

## 0. 판단

오너 안의 뼈대(타이밍 = 정확도, 미는 힘 = 방향)는 좋다. 그대로 쓰되 세 가지를 바꾼다.

| 오너 안 | 바꾼 것 | 이유 |
|---|---|---|
| "가장 낮은 수"가 80% | **낮은 구간**(주사위 둘이면 2–5, 하나면 1–2)이 나올 확률을 올림 | 한 숫자를 80%로 맞추면 원하는 칸에 거의 마음대로 가게 된다. 통행료 회피·독점 완성이 손재주만으로 결정되고 주사위의 긴장이 사라진다. 구간을 노리면 "위험을 줄이는 기술"이 되고 결과의 드라마는 남는다(포뮬러 D 기어와 같은 원리). |
| 최대 80% | **완벽할 때 구간 확률이 약 70%** (보정 확률 상한 60%, 상수 하나: `SKILL_CAP`) | 주사위 둘의 2–5 자연 확률은 27.8%. 60% 보정이면 0.6 + 0.4 × 0.278 ≈ 71%. 80%로 올리려면 상수 하나만 바꾸면 된다(보정 0.72 → 약 80%). 시뮬레이터로 판 길이·즉시 승리·역전률을 보고 정한다. |
| 미는 **속도**로 세기 | 미는 **길이**로 세기(손가락을 끌면 화살표가 늘어나며 미리 보임) | 속도는 떼기 전까지 보이지 않아 "왜 작게 됐지?"가 생긴다. 길이는 떼기 전에 화살표 색·눈금으로 보여 줄 수 있다: 짧게 = 작게(파랑), 중간 = 보통(회색), 길게 = 크게(주황). 던지는 연출의 세기도 이 길이를 따른다. |

여기에 보고서의 **보폭 선택**(주사위 하나/둘)이 겹친다. 둘은 다른 질문에 답한다.
- 보폭(전략): "얼마나 멀리 갈 수 있게 할까" — 1–6 또는 2–12. 턴마다 탭 한 번으로 고른다.
- 손맛 던지기(기술): "그 범위 안에서 작은 쪽/큰 쪽을 노릴까, 얼마나 정확하게" — 누르고 끌어서 놓는다.
두 단계가 한 동작 안에 들어가도록 UI를 짠다(§2). 복잡도 판단: 결정은 턴당 두 개(보폭, 노림)이고 둘 다 손가락
하나로 끝난다. 아무것도 하지 않고 가볍게 탭하면 지금처럼 보통 굴림이다. 그래서 처음 하는 사람에게는 지금과 같고,
익힌 사람에게는 기술이 된다.

## 1. 규칙 (엔진 계약)

`Roll` 액션 (규칙 버전 3, 보통·고급):
```ts
{ type: 'Roll'; playerId; stride?: 1 | 2; aim?: 'low' | 'high'; accuracy?: number /* 0..1 */; gauge?: number /* v1·v2 전용 */ }
```
- `stride` 없음 = 2. `stride: 1`이면 주사위 하나(1–6): 더블 없음(더블 보너스·추가 굴림·셋째 더블 없음).
- `aim` 없음 또는 `accuracy` 0 = 보정 없음(자연 분포).
- 보정: 확률 `p = SKILL_CAP × clamp(accuracy, 0, 1)`(기본 `SKILL_CAP = 0.6`, `src/engine/economy.ts`)로 결과를 노린 구간 안에서
  자연 분포에 비례해 뽑는다. 아니면 자연 굴림. 구간: 둘 = 낮음 2–5 / 높음 9–12, 하나 = 낮음 1–2 / 높음 5–6.
  둘일 때는 구간 안의 눈 조합(예: 합 4 = 1+3, 2+2, 3+1)을 시드 RNG로 고른다. 결과는 언제나 실제 눈 두 개다.
- 무인도 탈출 굴림에는 보폭·노림을 쓰지 않는다(더블이 필요하므로 자연 굴림).
- 규칙 버전 1·2 저장에는 예전 `gauge`(B7)가 그대로 동작한다. 버전 3에서는 `gauge`를 무시한다.
- `DiceRolled` 이벤트에 `stride`, `aim`, `accuracy`, `assisted: boolean`(보정이 실제로 적용됐는지)을 싣는다. UI는 이것으로 결과를
  설명한다("정확 92% · 작게 노림 → 성공").
- CPU: 보폭과 노림은 AI가 고른다(구간별 기대 점수 비교). 정확도는 난이도별로 시드 RNG에서 뽑는다(쉬움 평균 0.25,
  보통 평균 0.55, 둘 다 0–1 범위). 시뮬레이터도 같은 경로를 탄다.

## 2. 화면 (한 번의 동작)

1. **보폭 칩**: 주사위 패드 위에 작은 두 칩 `하나 1–6` / `둘 2–12`(기본 둘). 탭으로 바꾼다. 바꾸면 보드에서 닿을 수 있는
   칸 범위가 잠깐 밝아진다.
2. **누르기 = 타이밍**: 패드를 누르고 있으면 주사위가 흔들리고, 주사위 둘레의 **링 게이지**가 차올랐다 빠지기를
   반복한다(한 주기 약 1.4초, 게임 속도 설정을 따름). 링 꼭대기에 **초록 띠**(정확 구간)가 있다. 링 바늘이 초록 띠에
   있을 때 끌기를 시작하거나 떼면 정확도가 높다. 초록 한가운데 = 100%, 가장자리로 갈수록 0%로. 그 순간의 정확도가
   링 옆에 숫자로 뜬다.
3. **끌기 = 노림**: 누른 채로 손가락을 끌면 주사위에서 손가락까지 **화살표**가 늘어난다. 화살표 길이 눈금 세 칸:
   짧음 = `작게`(파랑, 아래 화살 아이콘), 중간 = `보통`(회색), 김 = `크게`(주황, 위 화살 아이콘). 화살표 끝에 지금 노림과
   구간(예: `작게 2–5`)이 붙는다. 정확도는 끌기를 시작한 순간에 고정된다.
4. **놓기 = 던지기**: 놓으면 화살표 방향과 길이로 던진다. 착지하면 주사위 아래에 짧은 결과 줄:
   `정확 92% · 작게 노림 → 성공 (4)` 또는 `정확 40% · 크게 노림 → 빗나감 (6)`. 1.5초 뒤 사라진다.
5. **그냥 탭** = 보통 굴림(노림 없음). 키보드 Enter도 보통 굴림.
6. **처음 한 번 안내**: 새 게임에서 사람의 첫 굴림 때 세 칸짜리 짧은 안내 카드(누르기 → 초록에서 끌기 → 길이로 노리기)를
   보여 주고, 규칙 화면에 같은 그림을 둔다. 설정에서 다시 볼 수 있다.
7. **CPU**: CPU 손이 패드를 누르고(링이 돈다), CPU의 정확도에 해당하는 위치에서 끌어 화살표를 늘린 뒤 놓는다. 결과 줄도
   똑같이 뜬다. 사람과 같은 규칙으로 보이게 한다.
8. **동작 줄이기**: 링은 돌지 않고 눈금이 숫자로 바뀌며(같은 시간), 화살표는 그대로 보인다.

## 3. 검증

- 단위: 구간 확률(완벽 정확도에서 낮음 구간 ≈ 0.6 + 0.4 × 자연 확률), 보폭 1의 더블 없음, 이벤트 필드, 시드 결정론,
  예전 버전 저장 호환.
- 시뮬레이터: 보고서 10의 목표(보통 AI 대 "무조건 산다" ≥ 75%, 탐색 플레이어 ≥ 55%, 즉시 승리 20–30%, 판 길이 ±15%)를
  `SKILL_CAP` 0.4 / 0.6 / 0.72에서 비교해 기본값을 정한다.
- 브라우저: 사람 굴림에서 링·화살표·결과 줄, CPU 굴림의 같은 표시, 그냥 탭 = 보통.

## 4. 구현 메모 (2026-10-08, UI)

§2를 그대로 구현했다(설계 요약 `docs/DESIGN.md` §2.4 "Skill throw", 코드 `src/ui/stage/skill.ts`·`SkillPad.ts`·
`skillGuide.ts`, `prompts.ts` 굴림 패드, `CpuHand.ts`, `Stage.rollResult`). **전략 모드에서만** 보인다
(`ruleFlags().skillThrow` / `strideChoice`: 고급 규칙 + 버전 3). 캐주얼은 예전 던지기 그대로(누르고 흔들고 밀어
던지기, 세기는 겉모습만). 정한 값과 달라진 점:

- **링**: 주사위 쌍을 두르는 경기장 모양(하나일 때는 원) SVG. 바닥에서 시계 방향으로 한 바퀴 = **1.4초 × 게임 속도 / 2**
  (기본 "보통"에서 1.4초, 가장 느긋하면 2.1초, 1초 아래로는 안 감). 초록 띠 = 꼭대기 **±12 %**(바퀴의 24 %, 1.4초 바퀴에서
  약 336 ms). 정확도 = 띠 가운데 100 %, 가장자리 0 %로 직선, 밖은 0 %. 30 Hz로 찍으니 한 프레임에 바퀴의 2.4 %(정확도
  20 %p)씩 움직인다: 매 바퀴 띠 가운데에서 1.2 % 안에 드는 프레임이 하나는 있으므로 90 % 이상은 언제나 가능하지만 쉽지
  않다. 너무 어려우면 `SKILL.band` 하나만 바꾸면 된다(태블릿에서 아직 못 봄).
- **보이는 값 = 보내는 값.** 끌기를 시작한(데드존을 벗어난) 프레임의 정확도로 고정한다. 바늘이 멈추고 숫자에 금테.
- **화살표 길이 구간**(주사위 크기 기준, 1600×1000에서 주사위 약 100 px, 800×450에서 약 43 px): 0.35 미만(최소 16 px)
  = 탭(보통), 0.35–1.5 = 작게(파랑 ▼), 1.5–2.7 = 보통(회색), 2.7 이상 = 크게(주황 ▲), 화살표는 3.6에서 멈춘다.
  화살표는 링 가장자리에서 시작해 끌기 길이만큼 늘어난다(손가락 끝과 정확히 같지는 않음: 누른 곳이 패드 어디든 되기
  때문). 무대(`contain: paint`) 밖으로 나가도 잘리지 않도록 던질 때의 비행 레이어처럼 게임 맨 위 임시 레이어에 그리고,
  무대와 같은 각도로 돌려 글자가 차례인 사람 쪽으로 똑바로 선다. 끝 라벨은 화면 밖으로 나가지 않게 화살표를 따라 당긴다.
- **세기 = 길이.** `dragStrength`(데드존 → 3.6에서 0 → 1, 직선) → `launchOf`(캐주얼 플릭과 같은 발사 표). 그래서 작게는
  부드럽고 짧게, 크게는 세게 화면 가장자리까지. 방향은 화살표 방향.
- **주사위 하나**: 둘째 주사위를 숨기고 첫째를 쌍의 가운데에 세운다. `planThrow`가 주사위 하나·둘을 모두 받고, 한 점에서는
  각도를 알 수 없어 무대의 각도로 비행 프레임을 만든다(`frameFromOne`). 엔진은 `[눈, 0]`으로 보고한다(`rolledFaces`).
- **결과 줄**: `정확 92% · 작게 노림 → 성공 (4)`(초록) / `빗나감`(빨강). 성공 = 합이 노린 구간 안. 보통·탭·무인도
  굴림에는 없다. 1.5초 × 속도 / 2 뒤 0.2초에 사라지고 아무것도 기다리지 않는다.
- **CPU**: AI가 고른 `{ stride, aim, accuracy }`를 손이 그대로 연기한다: 하나면 칩을 바꾸고(칸이 밝아짐), 누르고, 바늘이
  최소 0.45초 돈 뒤 그 정확도의 위치(턴에 따라 꼭대기 앞/뒤)에 멈추고, 그 구간 가운데까지 0.38초 끌고 놓는다. 전략 모드
  CPU 굴림은 캐주얼보다 약 0.5–1.9초 길다.
- **첫 굴림 안내**(설치당 한 번, `skillGuideSeen`), 설정 → "손맛 던지기 안내 · 다시 보기", 규칙 화면 9쪽.
  800×450처럼 낮은 화면에서는 무대 위 카드가 그림과 제목만 보인다(긴 설명은 규칙 화면·설정에).
- **동작 줄이기**: 링을 숨기고 정확도 숫자만 같은 박자로 바뀐다. 화살표는 그대로, 던지기는 제자리 굴림.
- B7 주사위 게이지는 버전 3에서 보이지 않는다(1·2 저장은 그대로).
- **확인 못 한 것**: 실제 태블릿에서의 손맛(띠 너비 ±12 %가 배울 만한지, 구간 길이가 손가락에 맞는지, 30 Hz 바늘이
  부드러운지). 이 컨테이너의 Chromium에서만 봤다.
